# 0.22.32 — fresh engineering authority reads

A successful publication recovery could stop when successive native authority
reads disagreed, leaving its renewable lease held until expiry. The preserved
v0.22.30 incident identifies that safe head-mismatch boundary; its historical
logs do not prove a particular HTTP cache or provider cause.

Authenticated native REST GETs now request cache revalidation with
`Cache-Control: no-cache`. Compliant caches must revalidate authority and gate
observations, including a lease checkpoint followed by release. Request limits,
paths, credentials, exact heads, sole-parent commits, non-force arbitration and
strict ownership rejection remain intact. There is no retry or forced update.
Inconsistent provider responses still fail closed; no consistency guarantee
or unperformed native incident reproduction is claimed.

Original CI-only HTTP/control/lease scenarios exercise successful
checkpoint-to-release with preserved publication metadata, changed authority
and ownership, concurrent update conflicts, and ignored cache revalidation.
They use synthetic metadata and an offline transport.

This source version is proposed. Distinct exact-head/base Security and
complete-diff QA, all actual objective gates and Actions-owned immutable release
publication remain required. The product stays English, safe Rust std only,
with zero Cargo dependencies and no unsafe/FFI or external runtime helper.
Engineering administration continues to use Python std and GitHub.
