# 0.22.33 — default-source CI fix-forward

Two engineering-only merges, PR59 and PR60, kept version 0.22.32 after Actions had
already published it for a different source. Actions publishes an immutable release
for every push to the default branch, and the registry refuses a second image for a
published version, so the `release` job failed on `02a536f` while every other job
passed. Mechanical delivery recorded that failed default CI.

This version carries no product code change since 0.22.32. It publishes a new
immutable version from the validated source, as PR55 did for 0.22.32.

Delivery also gains the missing way out of that state. A recorded `ci-failed` commit
is superseded only when its own native run completed without success and the commit
is a strict ancestor of the current default head. Pending, unknown, unverified or
rejected-dispatch records, unrelated heads and a missing or unfinished run still stop
delivery. The new head must still pass its own CI and publication verification.

The control-command transport now ends a failed run with a fixed diagnostic: the exception
class and numeric HTTP status only, never message text. Acquisition no longer reads native
dependencies for the Master and Triage roles, which ignore them. These are the only other
changes; the authentication, freshness, actor and sole-parent non-force rules are unchanged.

Original CI-only scenarios cover the superseded case, each non-success conclusion,
a failed new head, and eleven records that must stay fail-closed.

This source version is proposed. Distinct exact-head/base Security and complete-diff
QA, all actual objective gates and Actions-owned immutable publication remain
required. The product stays English, safe Rust std only, with zero Cargo dependencies
and no unsafe/FFI or external runtime helper. Engineering administration continues
to use Python std and GitHub.
