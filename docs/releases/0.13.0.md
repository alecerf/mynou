# Explicit season-pack acquisition and file-to-episode mappings

Acquire catalog episodes from one torrent by mapping each episode to an exact
video path. Ordinary episode jobs share the native torrent identity, verify the
whole payload and import their selected files under canonical season/episode
names. Absolute/anime-style filenames can be mapped explicitly without guessing
their numbering. Missing mapped files produce an error without selecting another
video. Unmapped files still download but are not imported by mapped jobs.

Use `series-pack ID --url … --mapping FILE`, the Bearer
`POST /api/series/ID/packs` route or **Acquire a mapped pack** in browser series
details. New series records can be saved without automatic acquisition using
`track-series --unmonitored`, API `enabled: false` or the browser checkbox.
Existing scopes retain their prior monitoring choice.

Submissions prevalidate up to 64 distinct episode/file mappings, accepted catalog
identities and already aired dates, relative paths, source-key conflicts and
request capacity. File mappings persist with jobs and remain immutable. Existing
episode requests are reused in every state. Confirmed partial batches recover
through repeat submission and deduplication; shared cancellation and transfer
controls retain source/library files. Public reports omit acquisition URLs.

The complete implementation remains Rust standard library only with zero Cargo
dependencies and no runtime helper or browser dependency. Earlier jobs load
without a mapping. Do not downgrade storage containing mapped jobs to an older
binary that does not understand that field.

This release provides explicit operator mapping. Automatic pack search/ranking,
selective download skipping, multi-episode videos and general alternate/anime
catalog numbering remain subsequent work. No personal-installation compatibility
or general performance improvement is claimed.

See the [pack guide](https://github.com/alecerf/mynou/blob/v0.13.0/docs/packs.md)
for CLI/API/browser operations, exact limits and persistence, and the
[roadmap](https://github.com/alecerf/mynou/blob/v0.13.0/docs/roadmap.md) for following
stages. GitHub Actions alone validates and publishes the source ZIP, static
Linux x86_64 binary, Docker image archive and checksum files.
