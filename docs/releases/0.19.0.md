# Mynou 0.19.0 — Plex requester policies

An account's watchlist now becomes durable demand with explicit opt-in profiles,
approval, bounded quotas and a captured library destination before acquisition.
Compatible accounts share one canonical job. Removing one account retains other
interests, operator work and imported media. Each poll verifies its token's user
identity and advances only its own complete successful cursor.

Guarded CLI/API/browser controls expose policies, pending decisions, usage,
partial failures and recorded notification outcomes. Immutable acquisition
captures survive policy/configuration edits and restart. Checked atomic snapshot
reservations precede format-4 job provenance; recovery does not duplicate jobs or
charges. Existing formats, canonical/source numbering and shared-group promotion
retain their established rules.

Original CI scenarios include multiple accounts and conflicts, concurrent
approvals, quota/retry/day rollover, partial/stale polls, source numbering,
removals, notification preferences, redaction, session/CLI guards, corruption and
restart. Local native-peer/Plex fixtures check acquisition ordering, captured
routes/profiles and exact path confirmation; existing routed Plex media needs no
native transfer. All five jobs passed for
`2388836a24ac02225a4171aa3d6bbbc32323b6c7` in
[run 37303359973](https://github.com/alecerf/mynou/actions/runs/37303359973):
489 Rust tests across 43 targets and four scheduler checks. GitHub Actions
published [v0.19.0](https://github.com/alecerf/mynou/releases/tag/v0.19.0) with
seven assets on October 5, 2026, at 11:32:55 UTC. Its tag and assets are immutable;
later changes require their own validation and patch release.

Rust 1.99.0 and the currently latest Actions remain pinned. The implementation
uses Rust std only with zero Cargo dependencies. No local tests, lint, builds or
demos run; GitHub Actions alone creates tags, releases and verified assets.
Requester polls acquire aired episodes individually. Notification preferences
record local outcomes; external transports and requester self-service remain
later work. The following release targets IRC announcement automation.
