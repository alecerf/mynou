# 0.22.35 — media-sized PAR2 file-backed recovery

Native PAR2 recovery capped protected content at 16 MiB and held every output in
memory. `Set::recover_single_to_file` (and its cancellable form) adds an original
std-only file-backed first stage for **one** described recoverable file: it reads
the damaged, truncated or missing input in bounded 1 MiB-at-most slices and writes
a new private output. Memory is `(erasures + 2)` slices plus a fixed 512 KiB
overhead, independent of file size. The existing in-memory APIs and their
16 MiB / 256-slice / 32 MiB limits are unchanged.

`StreamingLimits` defaults to 1 GiB, 32768 slices, eight erasures, 1 MiB slices,
64 MiB working memory and 2^33 field operations; each may be tightened and none
raised. Planning, available-row rank selection, exact coefficients and parity
reads finish before any file is created. `StreamingPlan` names an existing
private (no group/other access), non-symlink directory, a restricted file name and
an owner binding. The output is written to `<name>.partial`, read back and checked
(padded slice MD5/CRC32, whole-file MD5, first-16-KiB MD5, exact length), then
published with a hard link so an existing path is never replaced. Failure or
cancellation removes the partial file; a pre-existing partial or final path is
rejected untouched. The source is re-hashed before and after, and the input is
hashed in two passes and must match. `StreamedRecovery::verify` reopens and
re-verifies the output; its `policy_sha256` binds set, source, file, input, owner
and limits. No hostile-filesystem snapshot atomicity is claimed.

Not included: queue/import integration, multi-file streaming, automatic repair
or admission. Original CI-only synthetic fixtures cover content above 16 MiB under
a tight memory budget, damaged/truncated/missing input, nonzero rows, rank/work/
memory limits, altered source, cancellation and unpublished output. This version
is proposed until actual CI, Security/QA and Actions-owned publication.
