# Durable native transfer controls

Mynou now exposes its native transfer queue through the CLI and authenticated
API. List and inspect transfers, explicitly pause/resume them, assign durable
queue priorities and change per-file piece priorities. Higher-priority waiting
transfers start first, equal priorities use FIFO order, and active transfers are
not preempted. Transfer IDs are distinct from request IDs; controls affect all
requests sharing a transfer.

User pauses survive restart and are not undone by automatic retries. File
priorities change piece order while every file still downloads; `skip` and
selective pack acquisition are not implemented.

Optional global payload bandwidth limits and transfer policy overrides add
rate control with a bounded 16 KiB burst. Global rate caps remain mandatory;
local policy objects replace configured seeding defaults in full. Persistent
counters and seeding elapsed time support ratio/time policies based on verified
non-padding payload size and online seeding availability, including idle time.
Defaults remain unlimited for existing configurations. Accounting updates are
coalesced and flushed on clean shutdown; an abrupt crash can lose
the latest unflushed increments.

Controls and seeding limits preserve downloaded sources and imported library
files. There is no automatic cleanup. Each torrent still uses one active peer;
parallel peer transfers remain the next stage.

See the [transfer guide](https://github.com/alecerf/mynou/blob/v0.9.0/docs/transfers.md)
for commands, authenticated operations, configuration bounds, shared-transfer
behavior and remaining limits. The
[roadmap](https://github.com/alecerf/mynou/blob/v0.9.0/docs/roadmap.md) tracks the
later web interface and broader media-management features.
