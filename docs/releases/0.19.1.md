# Mynou 0.19.1 — Verified reuse of operator imports

A new requester could previously join an uncaptured operator job based on the
current configuration, even when that job was pending or its existing files
belonged to another destination. It now remains an uncharged conflict unless
the operator job is ready and every imported path is an existing regular file
beneath the requested destination. Symlinks, parent-path traversal, similar
directory prefixes, missing files and directories do not establish compatibility.

A recorded quality baseline must name the selected profile and pass its title
assessment. Imports without a baseline support only the unrestricted default
profile. Compatible completed imports still reuse the original job without
downloading, moving files or rewriting operator ownership. Requester jobs with
immutable acquisition captures retain their established sharing rules.

An original local-service regression covers rejected and accepted reuse, quota
accounting, unchanged operator journals and restart. All five jobs passed for
`83e6d1a40ac2d5abac0baf355a0011c58e49429a` in
[run 37305082540](https://github.com/alecerf/mynou/actions/runs/37305082540):
490 Rust tests across 43 targets and four scheduler checks. CI published
[v0.19.1](https://github.com/alecerf/mynou/releases/tag/v0.19.1) with seven assets
on October 5, 2026, at 11:48:49 UTC. Its tag targets the validated commit.
CI alone created the new tag, release and assets, preserving the v0.19.0 and
v0.18.0 tags and payloads. Later commits require their own complete workflow.
The code uses Rust std only, with zero Cargo dependencies. No local tests, lint,
builds, binaries or demonstrations run.
