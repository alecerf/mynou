# 0.22.34 — opt-in engineering worker leases

[Issue58](https://github.com/alecerf/mynou/issues/58) adds a bounded optional team
model to engineering control. Live control remains schema1 with one worker until
a separately configured, exact installed-source activation verifies actual
Security/QA records, objective gates and default CI. This proposal does not enable
team mode or launch another worker.

Schema3 provides server-read Issue areas, bounded worker capacity, exclusive
control work, sole-parent non-force arbitration, individual expiry recovery and
a singleton mechanical delivery lease. Exclusive or stale workers fence delivery;
leased linked Issues wait, and every worker-held branch is protected at audit and
again before deletion. Release, recovery and the three-attempt circuit breaker
retain a bounded per-Issue source/next-action handoff beside existing durable
migration/publication evidence.

Wake selection returns candidates, not launched compute. Authorized workers must
acquire their own scopes; expanded/shared engineering work must release and
re-scope. The hourly Task remains best-effort recovery, with no guaranteed Cloud
launch or quota-reset wake. Schema1 tooling fails closed on schema3.

Original CI-only scenarios cover competing areas/capacity, exclusive delivery,
expired recovery ordering, source-bound activation gates/races, interruption
handoffs and a worker arriving before branch deletion. This version is proposed:
no local checks were run, and distinct full-diff Security/QA, actual CI and
Actions-owned immutable publication remain required. Product runtime behavior
and its safe Rust std/zero Cargo dependency contract are unchanged.
