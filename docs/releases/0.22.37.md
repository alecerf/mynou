# 0.22.37 — opt-in parallel engineering team

Engineering control gains an opt-in team model for [Issue 58](https://github.com/alecerf/mynou/issues/58).
Schema-1 serial behavior is unchanged until a reviewed `enable-team` transition
and the trunk `team` bound are both in place.

Team mode adds a schema-3 `workers` table beside the unchanged serial
`lease`/`checkpoint`. Worker acquisition is routed by Issue labels read
server-side: `area:*` labels give the areas, while `area:control` or no area
label is exclusive. Rules: one lease per Issue, valid workers below the cap,
pairwise-disjoint areas, and exclusive work only on an empty team. Checkpoint,
release, attempt and recover select a worker by lease id; each expired worker
lease is recovered individually from native evidence. `wake` returns assignments
up to capacity and drains rather than starving a top-priority exclusive Issue.
The delivery lease stays a singleton, merges stay serialized, and versions are
assigned per merge. Schema-1 tooling rejects schema 3 rather than overwriting it.

Original CI-only scenarios (`engineering/tests/test_team.py`) cover state
validation, areas, capacity, drain, individual recovery, historical review
leases, enablement and command transport with synthetic refs. No product
runtime behavior changes; the product stays safe Rust std with zero Cargo
dependencies. This source version is proposed: distinct Security and full-diff
QA, actual CI and Actions-owned immutable publication remain required.
