# Library monitoring and controlled upgrades

Mynou now lists its own current ready imports and can search for better releases
under the configured movie or episode profile. `mynou upgrades` previews the
decision; `mynou upgrades --apply` queues eligible replacements. Authenticated
`GET /api/library` and `POST /api/upgrades` provide the same management surface.

Offline library listing and upgrade previews open read-only storage without
creating files, changing permissions or repairing journal tails. Fresh storage
returns no entries; interrupted tails require explicit writable recovery.

Per-entry monitor/unmonitor commands and API operations persist monitoring
policy. Background checks are disabled by default, including for existing
configuration files. Optional resolution cutoffs follow each profile's
preference order. An accepted baseline needs a strict quality-rank improvement.
If a deliberate profile change rejects the baseline, an accepted candidate can
replace it even with a lower raw rank. Additional seeds alone never trigger an
upgrade.

New automatic acquisitions record a release baseline. Earlier or explicitly
submitted imports without one remain ineligible until an explicit `baseline`
command supplies a release-title claim. Existing Plex content skipped at initial
acquisition is not adopted as an owned library entry.

An upgrade is a child request. The earlier ready entry stays current while its
child downloads, imports and confirms availability. Failed or canceled children
leave it current. A pending upgrade blocks unrelated same-media promotion, and
a ready child inherits the parent's current monitoring choice. Unique upgrade
filenames preserve the earlier import and all downloads; this release adds no
automatic cleanup.

With Plex enabled, confirmation requires the new file's `Part.file` path, not
merely a matching title. Optional path mappings support different shared-volume
paths in Plex and Mynou containers.

See the [library guide](https://github.com/alecerf/mynou/blob/v0.8.0/docs/library.md)
for configuration, preview/apply behavior, cutoffs, baseline limitations, and
Plex path mappings. Torrent queue controls, bandwidth/ratio policies, parallel
peers, and the web interface remain later stages in the
[roadmap](https://github.com/alecerf/mynou/blob/v0.8.0/docs/roadmap.md).
