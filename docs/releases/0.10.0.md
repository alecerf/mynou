# Bounded parallel peer transfers

Mynou can download verified torrent pieces from several TCP peers in parallel.
Set `downloads.max_peers` to an integer from one through eight; the default is
four, including for older configurations that omit the field. A value of one
provides a single-peer baseline. Global worker and per-transfer resource bounds
can reduce the effective count.

One coordinator owns piece selection, verified writes and completion. Pieces
have exclusive in-flight owners; failed or corrupt peer responses return work
for another peer. Completed downloads still pass final v1, v2 or hybrid
verification before becoming ready. There are no duplicate endgame requests or
selective file skips. File-priority changes apply to subsequent piece claims.

Worker results use bounded, cancellation-aware queues. Retired generations
cannot commit parallel file writes, and corrupt peers remain quarantined even
when their worker exits before its queued failure is read. Shared tracker/DHT
capacity alternates eligible task kinds and rotates torrent selection.

Known usable peers start alongside bounded background discovery. Private
torrent restrictions remain in force, and magnet metadata is authenticated
before parallel payload transfers. This release does not add uTP, WebTorrent,
webseeds, automatic NAT traversal or a complete persistent DHT table.

Durable pause/resume, priority/FIFO queue scheduling, aggregate bandwidth caps,
persistent accounting and ratio/time seeding policies from 0.9.0 continue to
apply. Controls retain downloaded data and library imports. Parallelism does
not bypass configured rate limits or promise a faster public-swarm download.

See the [transfer guide](https://github.com/alecerf/mynou/blob/v0.10.0/docs/transfers.md)
for configuration, resource bounds and control behavior, and the
[validation guide](https://github.com/alecerf/mynou/blob/v0.10.0/docs/validation.md)
for CI requirements and historical evidence. The
[roadmap](https://github.com/alecerf/mynou/blob/v0.10.0/docs/roadmap.md) tracks the
later web interface and broader media-management stages.
