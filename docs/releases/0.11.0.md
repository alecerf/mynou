# Browser management with Rust std only

Open `/ui` on the running Mynou service to manage requests, searches, owned
imports and native transfers. The interface is server-rendered HTML/CSS and
native browser forms; it uses no JavaScript, frontend framework, external asset
service or Cargo dependency.

Sign in with the existing API token. Mynou then uses a separate in-memory
browser session with an eight-hour absolute lifetime. Session/form tokens rotate
at login, logout and restart end sessions, cookies use HttpOnly/SameSite=Strict,
and HTTPS sign-in sets Secure. Form changes require both a matching form token
and same-origin checks. Browser cookies do not grant access to the Bearer API.

Jobs include filters, pagination, progress, details and recent history. Search
previews show release decisions without creating jobs or exposing acquisition
URLs. Record requests from the same page; source inputs are cleared after
preview. The owned library supports monitoring, one-time release baselines,
upgrade previews and explicit apply passes. Native transfers expose pause,
resume, queue/file priorities, counters and per-transfer policy overrides.

Bulk cancel/retry, monitor/unmonitor and pause/resume validate all identifiers
before changes begin. Up to 32 entries are handled independently, with visible
per-entry outcomes. Lists and detail files/history are limited to 50 rows per
page. Controls retain downloaded sources and library imports.

The embedded responsive stylesheet provides visible focus, labels, semantic
tables and keyboard navigation. Protocol/form CI scenarios do not establish
independent browser accessibility review or validation on a personal Plex
installation. This release remains a shared-operator interface with page
refreshes, not multi-user administration or full parity with the other managers.

See the [browser guide](https://github.com/alecerf/mynou/blob/v0.11.0/docs/web.md)
for deployment, authentication and exact bounds, and the
[roadmap](https://github.com/alecerf/mynou/blob/v0.11.0/docs/roadmap.md) for the
following series-management stage. GitHub Actions validates and publishes the
source ZIP, static Linux x86_64 binary, Docker image archive and checksum files.
