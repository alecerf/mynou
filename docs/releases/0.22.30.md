# 0.22.30 — canonical publication transport

GitHub Actions published v0.22.29 successfully, but the follow-up recovery client
requested a repository-root URL with a trailing slash. GitHub returns404 for that
route. This proposed correction uses the canonical repository endpoint while
preserving child routes, query strings, credentials and request/response bounds.

Original CI scenarios pass through the real REST client so publication mocks
cannot hide that routing regression. Unverified-publication checkpoints record
only a bounded native HTTP status when available; response bodies, headers,
credentials and signed storage URLs never enter the handoff.

Published v0.22.29 assets remain immutable. This source version is a proposal:
separate exact-head/base Security/full-diff QA, all objective gates, Actions-only
publication and actual current-default receipt reconciliation are still required.
Issue44 remains blocked by the distinct post-merge transport defect in Issue50
until native recovery and cleanup actually complete. No local checks, runtime
behavior, Cargo dependencies, paid infrastructure or scheduling changes are added.
