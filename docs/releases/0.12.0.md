# Durable series monitoring and episode calendar

Track a series once to retain its TMDB episode plan, monitoring choices and
refresh schedule. Plex show watchlist entries and series submissions now create
these durable records. The background worker discovers newly aired missing
episodes and records ordinary jobs for selection, verified torrent download,
import and Plex confirmation. Future episodes, unknown air dates and missing
catalog identities remain visible without premature automatic acquisition.

Use the browser's Series and Calendar pages or the new `track-series`, `series`,
series/episode monitor controls, `series-refresh` and `calendar` commands. Series
settings support optional catalog specials, an earliest monitored UTC date and
individual episode exclusions. The Bearer API provides the same operations.
Disabling monitoring preserves existing jobs and files. Removing a show from
Plex's watchlist also preserves its retained monitoring choice.

Refreshes use bounded catalog work and batches of at most 64 acquisitions.
Existing job identities deduplicate overlapping scopes and restart recovery.
Settings revisions reject late refresh results. Catalog failures retain the
last accepted plan and back off; duplicate numbering and changed known episode
identities require a mapping decision. A private verified snapshot shares the
request store's directory ownership and confirms writes after synchronization.

The calendar exposes dated episodes, monitoring and job state in bounded date
windows and pages. Unknown dates stay in series details. All implementation
remains Rust standard library only, with zero Cargo dependencies, native
HTML/forms and no external runtime helper.

Season packs, selective file acquisition and alternate/anime numbering are the
next series stage. This release does not claim full Sonarr or stack parity,
personal-installation validation or measured performance improvements.

See the [series guide](https://github.com/alecerf/mynou/blob/v0.12.0/docs/series.md)
for persistence, API/CLI operations and exact limits, and the
[roadmap](https://github.com/alecerf/mynou/blob/v0.12.0/docs/roadmap.md) for subsequent
stages. GitHub Actions alone validates and publishes the source ZIP, static
Linux x86_64 binary, Docker image archive and checksum files.
