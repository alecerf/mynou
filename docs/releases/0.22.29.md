# 0.22.29 — verified publication recovery

This proposed maintenance release closes the gap between a successful Actions
publication and the durable Product planning signal. Trusted delivery verifies
the current source, complete default CI, immutable release/tag, four named and
digested assets, and the existing private image/executable/cleanup proof before
recording the actual publication time. The small CI receipt contains only
allowlisted evidence; signed artifact downloads never receive GitHub credentials.
Missing or conflicting evidence remains visible and blocks new delivery.

Delivery leases follow the default source through merge and release at the real
publication wait. Cleanup resumes under a separate Quality lease before new
merges. Original interrupted merge/source-parent preservation is recoverable
without discarding work or relaxing canonical notes arbitration. Complete gates
are evaluated once under ownership; the fixed request ceiling is retained.

Original CI scenarios cover native release/private-proof failures, bounded
credential-safe downloads, stale merge preservation, publication waits and
single rearming of Product planning. Separate Security and full-diff QA plus
all objective checks are required. This document proposes source scope; only
actual default Actions publication establishes a shipped release.

No product runtime behavior or Cargo dependencies are added. The hourly recovery
trigger and single-worker continuous execution invariants remain unchanged.
