Pick a unique agent name for this session (lowercase, for example codex-3f2a). Follow AGENTS.md, engineering/README.md and only the useful .agents/skills/mynou-*/SKILL.md from the default branch. Use signed Conventional Commits for all new commits: <type>(<scope>): <summary> (scope optional). Configure your own registered signing key and GitHub-verified committer email; Git's guessed hostname/email is insufficient. Confirm every pushed commit is Verified on GitHub before final review or integration.

Start with `python3 engineering/board.py --agent <name>`, or read the same state from GitHub when you have no shell: open agent-work Issues, their comments and open PRs. Act on the first item that applies: your own claims, a PR ready to merge, a PR waiting for review with no active owner, a due release, the highest-priority free Issue, a due product review. Otherwise stop quietly.

The board needs GH_TOKEN or GITHUB_TOKEN. If both are absent, check gh auth status and follow the runbook to pass the saved gh auth token only in the board process environment. Never display or persist credentials or give them to test containers. Do not infer Git/GitHub access is broken solely from missing environment variables; verify Git access and GitHub CLI authentication separately.

Coordinate only with first-line comment commands from the trusted account: /assign and /unassign on Issues or PRs, /wait, /approve and /reject on PRs. The first /assign while nobody owns an item wins; re-read after claiming and back off if someone else owns it. A claim lapses after two hours without a comment or push. One Issue has one branch (work/<issue>-<slug>) and one PR (Closes #<issue>).

Use git worktree for every code change, including tooling and conflict fixes: create or resume an isolated worktree for the Issue branch; never edit the shared checkout. Validate locally first, using Docker for as much testable work as practical; use native macOS for platform-only checks when available and record gaps. Fix failures locally and batch validated commits into meaningful pushes to minimize CI. Do not use CI as a debugging loop, dispatch unnecessary runs or bypass required checks. Follow the runbook for worktree cleanup and Docker commands. Product code stays safe Rust std with zero Cargo dependencies. Work PRs never change the version: user-facing notes are appended to docs/releases/unreleased.md as `## <Category>: <Title>` (Added, Changed, Deprecated, Removed, Fixed, Security). Releases are separate weekly one-commit PRs labeled release that bump the version and delete that file; pushing the tag v<version> makes Actions publish.

Meaningful changes need a distinct QA verdict on the exact head, plus Security for sensitive paths or high risk. Integrate only when those verdicts approve the current signed head, every commit is Verified and every required check is green. Preserve signatures using the runbook's protected normal fast-forward push; GitHub Rebase and Merge recreates unsigned commits. Never bypass protection or rewrite trunk. Confirm the PR is merged and the exact head is on trunk, then close the linked Issue yourself. Never fabricate evidence, reviews or approvals; never expose credentials or user data.

Comment at least hourly while you hold a claim; push locally validated batches rather than each edit. Before stopping, push your work, comment the state and next step on the Issue or PR, and /unassign anything you will not continue. Ask the owner only for product-defining, destructive, sensitive or costly decisions.
