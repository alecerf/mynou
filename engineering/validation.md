# Bootstrap verification

Source, Skills, operational tools and offline scenarios are implemented. Their
own Actions results and real bootstrap PR review are pending until recorded in
the owning [Issue #1](https://github.com/alecerf/mynou/issues/1). No local tests,
lint, builds, policy checks or product binaries were run. Do not infer success
from this document; the live PR reviews/jobs are authoritative.

| Scenario | Deterministic coverage / live evidence |
| --- | --- |
| A / B user bug/feature | Native intent templates, one backlog, serialized roles, real bootstrap Issue/PR delivery |
| C security discovery | P0 selection; separate scoped Security lease/review and required risk gate |
| D UX discovery | Shared origin-labelled backlog; UX acceptance handoff to Web |
| E dead code | Quality requires reachability/public-contract evidence, normal CI/QA; no unsupported automatic dead-code proof |
| F stale branch | Unique work, active PR, Issue body/comment, lease, protected branch and changed-head guards |
| G recurring expertise | Catalog/Skill policy accepts reviewed additions; Master criteria, no speculative specialist zoo |
| H temporary expertise | Temporary in-worker roles; busy lease still rejects another worker |
| I QA disagreement | Latest rejected native COMMENT blocks; actual later current review is required |
| J same identity | COMMENT records plus distinct historical role leases; no formal self-approval required |
| K quota loss | Remote checkpoint preserved; expiry and recovery do not mark failure |
| L worker death | Explicit expiry; complete preservation/Issue/PR/CI evidence required for reclaim |
| M red CI | Every required job is inspected and red jobs prevent QA/delivery |
| N useful idle work | Evidence-based native queue, user priority and security precedence |
| O healthy idle | No executable work returns idle without fabricated improvement |
| P no progress | Three unchanged attempts release ownership and route to Triage |
| Q fresh session | JSON checkpoint reconstruction and documented GitHub-only control protocol |
| R cleanup | Exact merged-head proof, native closure/status/dependencies and safe branch guards |

Offline fixtures are deliberately labelled fake CI/reviews and use no network,
public content or credentials. They test mechanical decisions, not an LLM's
judgment. Actual independent logical Security/QA must still inspect each real
diff. The gate verifies recorded provenance/freshness; it does not prove reasoning.
Scheduling/permission limits are live observations, not simulated successes.
